# SSE 流式时序基准（本地桩）

> 被测对象：`app.planning.graph.run_stream` 的事件转发层
> 桩节点延迟：5.0ms × 15 个节点，重复 5 次

## 1. 结果

| 指标 | 值 |
|---|---:|
| 首事件延迟 TTFE（P50） | 0.09ms |
| 首事件延迟（最小） | 0.08ms |
| 整轮耗时（P50） | 230.44ms |
| 每轮事件数 | 31（15 stage + 15 summary + 1 result） |
| 顺序不变量违反 | 无 |
| 合规轮次 | 100.0% |
| 图上存在但无进度文案的节点 | ['main_meal_output'] |
| HTTP 层事件数 / 帧结构 | 8 / 正常 |

## 2. 读法

- TTFE 只包含转发与快照开销，不含任何模型或检索耗时；不能当线上首字延迟。
- 顺序不变量：每个节点的 `stage` 必须先于其 `stage_summary`，且 `result` 唯一且在最后。
- `main_meal_output` 没有进度文案，`run_stream` 会把它过滤掉，因此用户看不到该阶段；这不是测试遗漏，而是已记录的可观测缺口。
- 生产并行分支的到达顺序不固定，因此这里只校验“同节点先后”，不校验跨节点全序。
- HTTP 层：`TestClient 缓冲整个响应，TTFE 只能在进程内测；此处验帧形状与事件序列`（状态码 200，事件 8，result 唯一=True）。
