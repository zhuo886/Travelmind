# 评测参数与规模建议（2026-11-08）

> 回答两个问题：**(1) 该测哪些指标；(2) 每组要多少样本、分几组**，以及为什么。
> 现状：今日已有 A/B/C 各 n=2、安全 6 条、Judge 5 条、Reviewer 挑战 6 次、日期兜底 33 条、端到端 4 例（进行中）。
> 这些量级只够"机制证据"，不够"比率结论"。

## 1. 指标清单（按维度）

### 1.1 速度（工程价值，最能写进简历）

| 指标 | 口径 | 为什么需要 |
|---|---|---|
| 端到端 P50 / P95 | 每次 trial 的 wall clock | P50 说明典型体验，P95 说明用户会不会等到放弃 |
| 节点 P50 / max | planner / reviewer / time_check 分别统计 | 定位加速来自哪个节点（今日证据：reviewer −68%、time_check −74%、planner 无变化） |
| LLM 调用次数 | 每次 trial 的调用数 | 解释延迟结构：B 臂 5.0 次、C 臂 8.0 次 |
| 输入/输出 Token | 估算值 | 成本代理；注意是估算不是账单 |
| 拒绝耗时 | 不可行样本的端到端 | 硬拒绝要"快拒绝"，今日 16.5–69.0s vs 修复前 276.8s |

**规模要求**：P50 需要每臂 **n≥10** 才勉强稳定；P95 需要 **n≥20**（现有报告里 P95 一直显示"样本不足 n<20"就是这个问题）。

### 1.2 质量（确定性，可复现、不算钱）

| 指标 | 分母 | 含义 |
|---|---|---|
| FDR 完整交付率 / PDR 部分交付率 | 全部有效 trial | 交得出完整行程的比例 |
| HPR 硬约束通过率 | 已生成规划的 trial | 交付物是否违反 L0 |
| OMR 预期匹配率 | 已交付 trial | 是否符合 benchmark 的 allowed_outcomes |
| soft_score 均分 | 有分数的 trial | 确定性 100 分制（偏好/节奏/地理/天气/多样性） |
| L0/L1 码分布 | 按码计数 | 错在哪一类（今日唯一致命项：`opening_time_conflict`） |
| RRR 返工修复率 | 首版有 L0 的 trial | 返工到底有没有用 |
| OOR 池外实体率 | 全部景点引用 | 幻觉景点比例（今日 0） |
| MSR 必去命中率 | benchmark 标注必去的 trial | 只在 v2 起点名的 fixture 有意义 |

**规模要求**：比率类指标每臂 **n≥10** 才能报"X%"，n≥30 才能报两位有效数字。

### 1.3 语义质量（Judge）

| 指标 | 说明 |
|---|---|
| 总分均值 + 6 维均值 | preference_fit / pacing / geographic_coherence / time_realism / completeness / diversity_and_dining |
| 双评一致性 κ | 必须 k≥2 才有意义；`temperature=0` 下同一模型两次结果相同，κ 恒为 1，等于没有信息 |
| 覆盖率 | 有多少 trial 有可评路线（今日 5/6，A 臂上海无路线） |
| flags 分布 | 诊断用，不进结论 |

**规模要求**：被评 trial **≥15**，k=2；若要 κ 有信息量，两个评委要用**不同模型或不同温度**。

### 1.4 可靠性（Reviewer 到底行不行）

| 指标 | 分母 | 说明 |
|---|---|---|
| 缺陷检出率 | 注入缺陷的 run | 今日 4/5（漏 `missing_must_visit`） |
| 关键词命中率 | 同上 | 检出但说错理由也算不合格 |
| 干净样本误打回率 | clean run | 今日 1/1（错在"周一闭馆"推理） |
| clean 带错误提醒率 | clean run | 比误打回更细：通过了但说错话 |

**规模要求**：缺陷 **5 类 × k=3 = 15 run**；干净对照 **≥5 个案例 × k=2 = 10 run**（今日 clean 只有 1 个，"误打回 100%"没有统计意义）。

### 1.5 安全（不可行请求）

| 指标 | 分母 | 说明 |
|---|---|---|
| SRR 正确拒绝率 | 不可行 trial | 今日 6/6 |
| WAR 误接受率 | 不可行 trial | 今日 0/6 |
| 不安全交付率 | 不可行 trial | 交付了不可行行程的比例 |
| 过度拒绝率 ORR | 可行 trial | 反向指标：别把可行请求也拒了 |

**规模要求**：不可行机制 **≥4 类**（池空、物理时间、天气冲突、必去不可满足）× 3 臂 = **12 trial**；可行侧同时保留 ≥10 条才能算 ORR。

### 1.6 端到端真实链路（最大的空白）

| 指标 | 说明 |
|---|---|
| 成功交付率 | 真实高德 + 真实 intent，不注入候选池 |
| 节点序列完整性 | intent/candidate_react/planner/reviewer/time_check/finalize 是否都跑到 |
| 端到端耗时与调用数 | 今日单例 367.5s、10 次调用 |
| clarify 行为 | 信息不足时是否追问而不是编造 |
| OOR | 真实检索下是否还会出现池外景点 |

**规模要求**：**4–6 例**即可（单条 5–7 分钟，成本高），定位是"证明链路可用 + 抓链路级缺陷"，不是算比率。

### 1.7 确定性兜底（零成本）

| 指标 | 规模 |
|---|---|
| 日期解析准确率（显式/相对/天数） | 冻结语料 **33 条**，今日 100% |
| 结构化降级成功率 | 单测覆盖，不需要真实调用 |

## 2. 规模建议（三档）

| 档位 | 组数 | 每组 n | 真实 trial | 额外调用 | 预计耗时 | 能写什么 |
|---|---|---|---|---|---|---|
| **最小**（今天够用） | A/B/C 3 臂 | 6 例 | 18 | Judge 36 + 挑战 12 | ≈1.5h | 机制证据："Reviewer 把交付率 1/2 提到 2/2"这类，仍不能写百分比 |
| **推荐**（可写简历） | A/B/C 3 臂 + 安全组 + 稳定性组 | 10 例 / 4 类 / 1 例×k=3 | 30 + 12 + 9 = 51 | Judge 60 + 挑战 24 + e2e 4 | ≈3h（含 429 缓冲） | P50/P95、HP/OM/交付率、SRR/WAR、误打回率、Token 成本 |
| **完整**（论文级） | 上述 + D 臂（risk gate 回放，零成本）+ thinking 开/关 2×2 | 12 例 | 48 + 27 + 12 = 87 | Judge 96 + 挑战 24 + e2e 6 | ≈5h | 四臂消融 + 配置敏感性，可报两位有效数字 |

耗时假设（今日实测）：A 臂 1–2.5 min、B/C 臂 2–4 min、负样本 15–70s、Judge 每次 ~30s、Reviewer 挑战每次 ~10s、e2e 每次 ~6 min。

## 3. 分组设计（为什么是这几组）

| 组 | 变动项 | 回答什么问题 |
|---|---|---|
| A `planner_only` | 无审核 | 基线：光靠 planner 能交出什么 |
| B `planner_reviewer` | +Reviewer | 审核值不值这个成本 |
| C `+time_check` | +Time Check | 专项核查是否还有边际收益（今日 B/C 同分，Token +50%） |
| D 生产 risk gate（回放） | 门控 | 门控是否真的在分流（11-07 实测 skip 0/30，D≡C） |
| 安全组 | 不可行输入 | 会不会交付错误答案 |
| 稳定性组 | 同案例 k=3 | 单次结果是不是抖动（今日 planner 66–160s） |
| 配置组（思考链开/关） | env | 速度/质量取舍，且必须记录 `llm_config` |

## 4. 采样纪律（不做就等于白跑）

1. **每臂同源**：同案例、同 fixture 指纹、同模型、同温度，只有臂不同。
2. **记录 env**：`llm_config` 必须进 manifest 与每条 trial（本轮已实现）。
3. **失效样本分离**：429/超时归 `infra`，不能算 Agent 失败，也不进质量分母。
4. **判据先冻结**：L0/L1 码表、allowed_outcomes、Judge rubric 改了就重跑，不能混算。
5. **pass@k 只用同案例多跑**：跨案例池化会算错。

## 5. 当前缺口（按优先级）

1. **P95 与比率**：每臂 n=2 → 什么百分比都写不了；优先把 B/C 扩到 10 例。
2. **干净样本只有 1 个**：Reviewer 误打回率无法估计，需扩到 ≥5 例。
3. **不可行机制只有 2 类**：补"天气冲突"与"必去不可满足"两类。
4. **Judge κ 无信息**：同模型同温度，需换第二个评委模型。
5. **端到端只有 1 例成功**：需 4–6 例才能说链路稳定。
